# 内网版：主机双击运行，局域网多设备访问

Status: ready-for-agent

## 问题陈述

这个工具要在没有互联网的内网里，用于多台设备之间传递信息。现有的部署方式在这种环境下用不了：

1. **Docker 和 npm 部署要求联网和开发工具。**
   内网里的使用者没有这些条件，需要的是解压后双击就能运行的东西。
2. **编辑器打不开。**
   Monaco 从 jsDelivr 的 CDN 加载（`src/index.tsx:12`）。没有互联网时，页面会一直停在加载状态。
3. **其他设备上的复制按钮总是失败。** 复制用的是
   `navigator.clipboard`。浏览器只在 HTTPS 或 localhost 下提供这个接口。其他设备通过
   `http://192.168.x.x:3030` 访问时，复制按钮每次都提示 "Copy failed"。
4. **关掉窗口就丢数据。**
   服务端默认只把文档放在内存里。在 Windows 上关掉控制台窗口，进程就结束了，所有文档随之丢失。
5. **双击后什么也看不到。**
   日志默认只输出 error 级别，所以控制台是空白的。端口被占用时，程序直接崩溃，窗口一闪而过。
6. **其他设备不知道该访问哪个地址。** 主机上显示的分享链接以 `localhost`
   开头，其他设备打不开。
7. **重启后找不到旧页面。** 不带 `#`
   的地址会新建一份随机文档，界面上没有任何入口能回到之前的页面。

## 解决方案

内网版放在长期分支 `intranet` 上，决策依据见
[ADR 0006](../../docs/adr/0006-intranet-release-on-long-lived-branch.md)。从使用者的角度看：

- 在主机上解压 zip，双击
  `rustpad.exe`。控制台窗口用中文显示局域网访问地址，同时主机的浏览器自动打开首页。
- 其他设备在浏览器里输入控制台上显示的地址，就能打开首页。
- 首页有三项内容：打开页面（输入页面 id 或粘贴链接）、新建页面、本设备的最近页面列表。
- 所有复制按钮在其他设备上也能用。
- 文档写进 exe 同目录下的 `rustpad.db`，关掉窗口再启动，内容还在。
- 程序出错时，窗口停住并用中文说明原因，等待按键。

主分支（在线版）只接收复制功能的修复。

## 用户故事

### 主机使用者

1. 作为主机使用者，我想解压后双击 exe 就能运行，这样我不需要安装任何东西。
2. 作为主机使用者，我想启动后在控制台上看到局域网访问地址，这样我能告诉其他人该访问哪里。
3. 作为主机使用者，我想启动后浏览器自动打开首页，这样我能直接从最近页面里选一个继续。
4. 作为主机使用者，我想关掉窗口再启动后页面内容还在，这样关窗口不会让我丢数据。
5. 作为主机使用者，我想在端口被占用或数据文件写不进时看到中文原因，而不是窗口一闪而过，这样我知道该怎么处理。

### 访问设备使用者

6. 作为手机或其他电脑的使用者，我想输入主机地址就能打开首页，这样我能新建页面或打开别人发给我的页面。
7. 作为访问设备使用者，我想复制按钮在 http 地址下也能用，这样我能把内容带到这台设备的其他程序里。
8. 作为访问设备使用者，我想首页只显示我这台设备打开过的页面，这样其他人的页面不会暴露给我，我的页面也不会暴露给别人。
9. 作为任何设备的使用者，我想把用不到的页面从最近页面列表里移除，这样列表不会越积越长；移除不会删掉主机上的数据。

## 实现决策

### 分支与同步

- 内网版的全部改动只放在 `intranet`
  分支上。分支上不设构建模式或开关，内网版的行为无条件生效。
- 复制降级对在线版也有用，所以它先进 main，再合并到 `intranet`。
- 每次发布内网版之前，用 `git merge main` 把 main 合并进
  `intranet`，不用 rebase。

### 复制降级（main）

- `navigator.clipboard` 不存在或 `writeText` 抛错时，改用隐藏文本框加
  `document.execCommand("copy")`。降级方案也失败时，仍提示 "Copy
  failed"，不能假装成功。
- 5 个复制入口都走同一个函数：`src/Sidebar.tsx:73`、`src/SingleDocView.tsx:402`，以及
  `src/BlockPageView.tsx` 中的 3 处。

### 本地 Monaco

- `@monaco-editor/react` 的加载器改为使用本地安装的 `monaco-editor`
  包，不再访问任何 CDN。Monaco 的 worker（编辑器后台线程）也由本地构建产物提供。
- 打开构建后的页面时，浏览器不能向任何非本机地址发出请求。`@monaco-editor/loader`
  的默认配置里写死了 jsDelivr 地址，所以构建产物里一定会出现这个字符串；判断标准是实际请求，不是字符串。
- 删除 `src/Sidebar.tsx` 里的 GitHub 链接。“Read the
  code” 按钮保留，因为它载入的是打包进前端的源码，不联网。

### 服务端启动体验

- 启动时用 `println!` 打印中文横幅，内容包括访问地址
  `http://<局域网IP>:<端口>/`。局域网 IP 按系统路由表选出，做法是让 UDP 套接字 connect 到一个外部地址，再读本端地址。这一步不发送任何数据包，也不新增依赖。选不出来时，打印
  `localhost`，并说明其他设备需要用主机的 IP 访问。
- 横幅同时说明数据存在哪里。没有设置 `SQLITE_URI`
  时，明确提示“未开启持久化，关闭窗口后数据丢失”。
- 当前工作目录下找不到 `dist/index.html`
  时，打印醒目的中文警告，并给出当前工作目录，程序继续运行。开发时用
  `npm run dev` 提供前端，本来就没有 `dist`。
- 端口被占用、`SQLITE_URI`
  无法打开、配置值无法解析时，用中文说明原因和处理办法（例如修改 `.env` 里的
  `PORT`）。程序有控制台时等待按键，再以非零退出码退出。判断有没有控制台用标准库的
  `IsTerminal`。
- 在 Windows 下，监听成功后用默认浏览器打开
  `http://<局域网IP>:<端口>/`，即首页。其他系统不自动打开浏览器，所以在 WSL 里开发时不会弹出浏览器。

### 首页与最近页面

- 内网版里，不带 `#` 的地址显示首页，不再新建随机单文档。`#page:<id>`、`#<id>`
  和 `#folds:` 前缀的处理方式不变。
- 首页有三项内容：
  - “打开页面”输入框：接受页面 id，也接受包含 `#page:<id>` 的完整链接。
  - “新建页面”按钮：生成新 id，跳到 `#page:<id>`。
  - 本设备的最近页面列表：每行显示页面标题（没有标题时显示页面 id）和本设备最后一次打开的时间，按这个时间从新到旧排序。每行可以“从列表移除”，不需要确认。
- 最近页面单独存在浏览器本地存储的一个键下，不复用块快照。块快照在存储配额不够时会被淘汰（`src/blockModeSync.ts:139`），而且它是缓存，不是数据源。
- 打开一个分块工作区页面时，写入或更新这个页面的最近页面记录。页面标题变化时，同步更新记录里的标题。单文档不写入最近页面。
- 分块工作区的侧边栏增加 “Home” 入口，点击后回到首页。
- 界面文字保持英文。

### 打包

- 打包脚本在 WSL 里运行。脚本依次构建 wasm、构建前端，再调用 Windows 侧的
  `cargo.exe` 编译 `x86_64-pc-windows-msvc` 版本的服务端，最后在 `release/`
  下生成 zip。`release/` 加入 `.gitignore`。
- zip 里有四项内容：
  - `rustpad.exe`，即重命名后的 `rustpad-server.exe`；
  - `dist\`；
  - `.env`，写着
    `SQLITE_URI=sqlite://rustpad.db`、`PORT=3030`、`RUST_LOG=warn`；
  - `使用说明.txt`。
- 数据文件 `rustpad.db`
  在第一次运行时自动生成。从资源管理器双击时，工作目录就是 exe 所在文件夹，所以
  `.env` 和 `dist` 都按工作目录查找。
- `使用说明.txt` 用中文写，内容包括：
  - 先解压再运行；
  - 首次运行时防火墙弹窗要点“允许”，以及手动放行端口的方法；
  - 其他设备怎样访问；
  - 数据文件在哪里、怎样备份；
  - 怎样从首页继续之前的页面，并提示清除浏览器数据会丢失最近页面记录，但页面本身还在主机上；
  - 怎样修改端口。

## 测试决策

### 什么是好测试

测试只检查外部可观察的行为：复制是否真的走了降级路径、首页列出哪些页面、构建产物里有没有外部地址。不检查内部函数怎样拆分。

### 被测模块与用例

- **复制降级**：用浏览器测试，从一个非安全上下文的地址访问（用 WSL 的局域网 IP，不用 localhost），点击复制后应该提示 "Copied!"，剪贴板内容应该和预期一致。在
  `navigator.clipboard` 存在的环境下，行为保持不变。
- **最近页面记录模块**：用 `node --test`
  做单元测试，存储对象由测试注入，覆盖以下用例：
  - 写入后能读出；
  - 重复打开同一页面只更新时间，不重复记录；
  - 按时间从新到旧排序；
  - 移除一条记录不影响其他记录；
  - 存储里的数据损坏时返回空列表，不抛错。
- **首页**：用浏览器测试，覆盖以下场景：
  - 不带 `#` 的地址显示首页；
  - 新建页面后跳到 `#page:<id>`，回到首页时列表里有这一页；
  - 在页面里改标题后，首页显示新标题；
  - 移除记录后，列表里不再有这一页，但用链接仍能打开它，内容不变；
  - 输入 id 或完整链接都能打开页面。
- **服务端**：`cargo test`
  全部通过。局域网 IP 的选取逻辑和横幅文本生成写成可单独测试的函数。
- **构建产物**：用浏览器测试打开构建后的页面，拦截并记录所有发往非本机地址的请求；编辑器加载完成时，记录应该为空。不用搜索 URL 字符串的办法：`@monaco-editor/loader`
  的默认配置和 Monaco 的代码里本来就有外部 URL 字符串，搜到了也不代表会联网，搜不到也不能证明不联网。
- **打包**：在 Windows 的一个临时目录里解压 zip，从 WSL 调用 Windows 启动
  `rustpad.exe`，再从 WSL 访问主机地址，确认首页能打开、编辑器能加载、`rustpad.db`
  已经生成。

### 不做自动化、必须实机验证的

以下项目只能由用户验证。在用户反馈之前，一律标为“未验证”：

- 在资源管理器里双击启动；
- 首次运行时的防火墙弹窗；
- 真实手机或其他电脑通过局域网访问；
- 在真实的断网环境下，编辑器能加载。

## 范围外

- 界面中文化。
- 服务端的页面列表接口、页面删除功能。
- GitHub Actions 发布内网版。
- Windows x64 以外的主机平台，以及 IE 等老旧浏览器。
- 自签名 HTTPS。
- 程序自动修改防火墙规则。
- 单文档模式进入最近页面。

### 已确认的环境事实

以下事实于 2026-10-01 核实：

- 这台机器的 WSL 里有 `x86_64-pc-windows-msvc`
  的 rustup 目标，但没有 MSVC 链接器。Windows 侧有
  `C:\Users\Shy\.cargo\bin\cargo.exe`、`stable-x86_64-pc-windows-msvc`
  工具链和 Visual Studio 2022 BuildTools（`VC/Tools/MSVC` 下有 `cl.exe` 和
  `link.exe`）。从 WSL 调用 `cargo.exe`，在 `/mnt/c/...`
  目录下编译一个最小程序能成功，运行时能正确输出中文。带 C 代码的依赖（`libsqlite3-sys`）还没有实际编译过，由 05 验证。
- 构建要在 `/mnt/c/...` 下的目录进行，不要直接在 `\\wsl$` 路径上编译。
- `@monaco-editor/loader` 的默认配置里写死了
  `https://cdn.jsdelivr.net/npm/monaco-editor@0.43.0/min/vs`。
- 现有浏览器测试要求先手动启动 `npm run dev`（`127.0.0.1:5173`）和
  `PORT=3030 cargo run -p rustpad-server`。
- 打包脚本依赖 Windows 侧的 `cargo.exe`
  和 MSVC 工具链。它们被移除后，打包就会失败。
