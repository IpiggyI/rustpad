# 01：在折叠 Markdown 标题后回车创建同级标题

**What to build:**
在单文档模式和分块工作区中，用户于已折叠 Markdown 标题末尾按普通回车，可在整个折叠区之后继续编写同级标题，原内容保持折叠。

**Blocked by:** 无，可立即开始。

**Status:** ready-for-agent

- [x] 仅在 Markdown、单光标、无选区、光标位于已折叠标题行末且没有处于输入法组合期间时触发新行为。
- [x] 在当前折叠区的全部内容之后插入同级标题，沿用原来的标题级别，不复制标题文字；新标题标记后保留一个空格，光标停在该空格之后。
- [x] 原折叠内容保持隐藏，新标题可见；验证正文内容、实际隐藏范围与光标位置，不能只验证插入字符串。
- [x] 折叠区包含子标题时，插在全部子标题内容之后；文末和已有后继同级或更高级标题两种情况均正确处理，不修改既有正文。
- [x] 两种模式使用相同语义。其他语言、展开的标题、标题中间、多光标、选区、带其他修饰键的命令和输入法组合期间保持原有行为。
- [x] 输入法候选确认用的回车不额外创建标题，组合结束后的正常回车仍可触发。
- [x] 插入作为一次可撤销正文编辑，撤销与重做得到正确正文；另一客户端收到相同插入，现有协同机制继续工作。
- [x] 用项目测试覆盖可独立验证的边界，并用真实编辑器执行两种模式的上述场景；检查能在插入位置、级别、折叠或光标行为错误时失败。

## Comments

实现于 `ccaedc6`，浏览器脚本前提补全于 `be57b32`。

判断逻辑是 `src/markdownFolding.ts` 的纯函数 `planHeadingEnter`，由
`scripts/headingEnter.test.ts` 覆盖 11 项；编辑器接线由
`scripts/headingEnter.browser.mjs` 覆盖 38 项，单文档与块编辑器各 19 项。

验证方式：`npm run check` 无错，`npm test` 152 项通过，`npm run test:browser`
38 项通过。两处变异确认检查不是空过——把插入位置改成标题行之后，节点测试失败 2 项、浏览器套件从 38 掉到 2，首个失败是隐藏行范围断言；把标题级别多加一个
`#`，节点测试失败 5 项。

未验证：系统原生输入法候选窗口。浏览器套件用 Chromium 的组合输入接口模拟，这不等同于真实输入法。
