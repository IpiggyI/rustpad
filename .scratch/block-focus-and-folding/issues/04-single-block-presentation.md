# 04：默认使用单块展示并保留切块时的编辑状态

**What to build:**
用户进入分块工作区时默认只查看当前块，可以切回堆叠展示；切块和切换展示方式都保持编辑连续性，复制与导出仍读取正确内容。

**Blocked by:** 03：通过侧栏选择和定位当前块。

**Status:** ready-for-agent

- [x] 提供单块展示和堆叠展示的明确切换入口。展示方式按设备、按页面记住，没有记录时默认单块展示。
- [x] 单块展示仅显示当前块正文，并占满主编辑区域；正文上方显示当前块名称、语言以及复制和导出入口。
- [x] 单块展示不受堆叠中的块高度或整块折叠状态影响，块内部折叠继续生效；不能为显示当前块而改写共享的整块折叠状态。
- [x] 切回堆叠展示时恢复各块已保存的高度与整块折叠状态，并定位到同一当前块；切入单块展示时显示当前块。
- [x] 本次页面打开期间，切块后返回保留各块的光标、滚动位置和撤销记录；展示切换同样不能丢失这些状态。
- [x] 快速输入后立即切块或切换展示方式，输入和未完成的协同操作仍正确保留。验证方案包含切换时尚未确认的编辑，不能只测试网络空闲时切换。
- [x] 关闭重开后恢复展示方式、当前块和已有折叠记忆；不新增跨重开保存光标、滚动或撤销记录的要求。
- [x] 复制和导出继续覆盖原有范围。远端修改非当前块后，读取结果不得直接采用过期缓存，也不得在读取失败时伪装成成功。
- [x] 空清单显示无当前块的新增入口，不因单块展示而自动创建块；当前块被远端删除时沿用导航票的选择规则。
- [x] 两个设备的展示方式和当前块相互独立，块正文及原有共享布局继续同步。单文档模式继续保留，两种模式不搬移正文。
- [x] 实施前核实编辑器、协同连接和正文缓存的生命周期，再选择满足上述行为的实现方式；不预设销毁编辑器是安全的，也不引入无独立用途的基础设施重构。
- [x] 完成真实浏览器切换、编辑、撤销、折叠和复制导出验证，并检查实际正文、光标、滚动、撤销结果及另一客户端收到的内容；不以编辑器未报错作为验收证据。

## Comments

生命周期决策见
[ADR 0004](../../../docs/adr/0004-block-editors-stay-mounted-per-block.md)：每个块的编辑器在页面打开期间常驻挂载，挂载只按块 id 决定，展示方式和
`collapsed`
都只控制可见性。这条决策先经过一次只读顾问评审；顾问最初主张把协同状态从编辑器解绑到模型，被"票据禁止无独立用途的基础设施重构"和"堆叠展示全展开时今天已经为每块挂一个实例和一条连接"两条理由推翻后改判。

`Rustpad.dispose()` 从同步关闭改为可等待关闭：先置编辑器只读，按既有确认顺序排空
`outstanding` 和 `buffer`，成功后才关闭连接，失败显式报错。`beforeunload`
警告保留——浏览器退出不等待 Promise，异步关闭不能当作送达保证。复制导出改走一次新的完整服务端历史读取，先等本地待确认操作，失败即报错，不再回退到旧快照。

验证方式：`npm run check` 无错，`npm test` 199 项通过，`npm run test:browser`
75 项通过，`npm run build`
通过。四处变异：删掉展示方式持久化（3 项节点测试照常通过，浏览器 16 掉到 1）、让复制返回缓存正文（16 掉到 5）、在 React
key 里混入展示方式强制重挂载（16 掉到 5）。

一次跨厂商验收评审发现一处高危缺陷并已修复：`syncFailure`
原本是永久闩锁，一次瞬时断线若恰好发生在复制等待期间，该块的复制导出会在整个页面会话里持续报错，且之后正常卸载会弹出并未发生的"改动未保存"。现在只有终局失败（连续五次断线的失同步、正在关闭、已关闭）才闩锁。双向验证：还原成永久闩锁后，"持续断网仍显式报错"一条照常通过，"恢复后新的复制应当成功"一条失败。

未验证：两台设备用的是同一浏览器的两个上下文，不是两台物理设备；输入法用 Chromium 的组合输入接口驱动，不是真实输入法。
