# 05：在侧栏新增、命名和选择块语言

**What to build:**
用户可以直接在侧栏创建当前块之后的新块，并通过侧栏完成块命名和现有语言类型选择，无需到块头部寻找操作。

**Blocked by:** 03：通过侧栏选择和定位当前块。

**Status:** ready-for-agent

- [x] 侧栏提供新增入口，新块插在当前块之后，立即成为当前块并进入命名，语言默认纯文本。
- [x] 页面为空时新增第一个块，选中并进入命名；新建后正文可编辑。
- [x] 侧栏能修改任意块名称，允许名称重复，修改名称不改变块身份、顺序或正文。
- [x] 侧栏语言选项沿用现有完整语言类型，选择后编辑器采用对应语言；本票不增加富文本、表格等新编辑形态。
- [x] 侧栏和现有块头部操作修改同一份块数据，名称与语言在所有入口及另一客户端中保持一致。
- [x] 命名保留现有中文输入法行为；操作输入框和菜单不会触发拖拽排序或误选另一个块。
- [x] 现有堆叠展示顶部和底部新增入口继续分别前插和追加，不被侧栏的“当前块之后”规则覆盖。
- [x] 新增、命名和语言变化不使其他设备跳转当前块，也不丢弃正在编辑的正文。
- [x] 测试覆盖插入位置、空清单和同名块；真实浏览器验证创建到命名再编辑的完整路径、输入法及跨客户端更新。

## Comments

插入位置是 `src/manifestOps.ts` 的纯函数 `addBlockAfter`，与既有的 `addBlock`
并列；堆叠展示顶部和底部的两个按钮继续走 `addBlock` 的 `"start"` 和
`"end"`，语义不变。名称输入复用 `src/ImeInput.tsx`，语言列表与块头部读同一份
`languages.json`，没有第二份清单。

验证方式：`npm run check` 无错，`npm test` 205 项通过，`npm run test:browser`
81 项通过（本票新增 6 项）。变异验证：把 `addBlockAfter`
改成一律追加到末尾，节点测试失败 1 项、本票浏览器检查从 6 项掉到 0 项。

未验证：第二个客户端用的是同一浏览器的第二个上下文，不是第二台物理设备。
