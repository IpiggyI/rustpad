# 07：通过侧栏菜单和拖拽调整块顺序

**What to build:**
用户能在侧栏直接调整块顺序，使用菜单完成精确移动，使用鼠标或触摸手柄拖拽并在长列表边缘自动滚动。

**Blocked by:** 03：通过侧栏选择和定位当前块。

**Status:** ready-for-agent

- [x] 每个侧栏项提供排序菜单，沿用上移、下移、置顶和置底语义；边界操作不改变顺序。
- [x] 只有专用手柄启动拖拽，点击导航、命名、语言选择、菜单和正文选区操作不会误触发排序。
- [x] 鼠标和触摸均能拖拽，界面明确显示预期落点；侧栏列表较长时，靠近上方或下方边缘会向对应方向自动滚动。
- [x] 拖拽期间只在本机预览顺序，松手才提交排序；取消或中断拖拽不写入未完成的预览结果。
- [x] 提交基于稳定块身份和最新清单定位，拖动期间远端新增或删除的块不被陈旧数组覆盖。
- [x] 移动目标已经被远端删除时安全结束操作，不重新创建该块；本票不扩大现有同步层对人为并发结构修改的保证。
- [x] 排序后仍选中同一块，正文、标题、语言、高度和折叠记录不变；其他设备收到块顺序变化，但不跳转当前块。
- [x] 堆叠展示保留现有块头部排序入口，侧栏与块头部操作体现同一顺序。
- [x] 测试覆盖移动边界、相对顺序及拖拽期间清单变化；真实浏览器验证鼠标、触摸、长列表自动滚动、取消和提交次数。

## Comments

提交逻辑是 `src/manifestOps.ts` 的纯函数
`reorderBlockByPreview`：它以**最新清单**为基准，从拖拽预览顺序里找出第一个仍然存在的后继块，再交给既有的
`moveBlockBefore`。因此拖拽期间远端新增的块不会被陈旧数组抹掉，远端删除的块会被跳过，被移动的块若已被远端删除则原样返回，不重建它。本票没有扩大同步层对并发结构修改的保证。

拖拽期间只更新本机预览，指针抬起才提交一次。

验证方式：`npm run check` 无错，`npm test` 217 项通过，`npm run test:browser`
101 项通过（本票 8 项），`npm run build` 通过。

变异验证两处。把提交改成直接套用拖拽开始时的数组：节点测试失败 1 项，正是"拖拽期间清单新增了块"那条；浏览器 8 项不变，因为远端并发按分工由节点层覆盖。让每次指针移动都提交一次：浏览器从 8 项掉到 2 项，失败信息为
`mouse drag should commit once, wrote 2`。

未验证：触摸拖拽用 `pointerType=touch`
的指针事件模拟，不是真实触摸屏；第二个客户端是同一浏览器的第二个上下文。
