# 06：确认删除块并保留零块页面

**What to build:**
用户从侧栏或现有块头部删除块前能核对块名，删除后保持明确的当前块落点，并且删到零块的页面重开后仍为空。

**Blocked by:** 03：通过侧栏选择和定位当前块。

**Status:** ready-for-agent

- [x] 侧栏和现有块头部删除入口都要求确认，提示中显示目标块名称。取消不会删除块或改变当前块。
- [x] 删除绑定块身份；即使名称重复，或确认期间块发生排序，也只删除用户确认的目标块。
- [x] 复用导航票定义的选择规则：删除当前块后优先选择原顺序中的后一个，没有后一个时选择前一个；删除其他块不改变当前块，不另建一套回退逻辑。
- [x] 允许删除最后一个块。零块页面没有当前块，显示可用的新增入口，刷新或关闭重开后仍然为空。
- [x] 已保存的合法零块清单与尚未初始化的页面明确区分。原有新页面初始化行为不因支持零块清单而意外改变。
- [x] 第二设备打开零块页面时也保持为空，不能用旧缓存或默认播种重新创建块。
- [x] 从零块页面通过现有新增入口创建第一个块后，可正常选择和编辑；侧栏新增入口接入后使用相同空页面语义。
- [x] 删除继续沿用现有块清单与本地布局清理范围，不增加服务端孤立正文删除或块回收站。
- [x] 远端删除无需本机再次确认；本机当前块按导航票规则处理，不能残留已删除块的正文界面。
- [x] 测试覆盖取消、同名目标、最后一块、重新初始化和旧缓存；真实浏览器验证删除后重开、第二设备打开及空页面再新增。

## Comments

本票的清单初始化部分在票 02 就已落地：`decideManifestInit` 接受 `blocks: []`
的有效清单，把非空但解析失败的文本当作损坏而不是新页面，并且在首轮完整历史回放结束前不初始化、不播种。决策见
[ADR 0005](../../../docs/adr/0005-empty-manifest-is-a-real-page-state.md)。本票补的是确认对话框、零块页面界面，以及下面这条票据原文之外的标准。

**新增标准（票据原文没有）**：服务端文档非空但解析失败时，`decideManifestInit`
返回 `unusable`，`useManifest`
永远不会就绪。此前用户看到的是一页禁用控件，没有任何说明——这是静默失败。现在页面会明说块清单读不出来，并且仍然拒绝覆盖损坏文档：拒绝覆盖是决策，沉默才是缺陷。

验证方式：`npm run check` 无错，`npm test` 209 项通过，`npm run test:browser`
93 项通过（本票 12 项），`npm run build` 通过。

变异验证经过两轮。第一个探针（把零块清单排除出"有效清单"）只让节点测试失败 2 项，浏览器 12 项照常通过——因为它把空页面推进了"损坏"分支，而损坏页面和空页面同样没有块，当时没有断言能区分二者。换用真正触发重新播种的探针后，浏览器从 12 项掉到 6 项。随后补上了区分这两种状态的断言：空页面重开后不得出现损坏提示，损坏页面不得像空页面那样提供新增入口。补完之后，第一个探针也能让套件从 12 项掉到 6 项。

未验证：第二台设备用的是同一浏览器的第二个上下文；服务端清理或重启之后零块页面是否仍然为空没有验证，按 ADR
0005 这依赖部署时是否设置 `SQLITE_URI`。
