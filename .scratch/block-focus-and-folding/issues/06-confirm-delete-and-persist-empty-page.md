# 06：确认删除块并保留零块页面

**What to build:**
用户从侧栏或现有块头部删除块前能核对块名，删除后保持明确的当前块落点，并且删到零块的页面重开后仍为空。

**Blocked by:** 03：通过侧栏选择和定位当前块。

**Status:** ready-for-agent

- [ ] 侧栏和现有块头部删除入口都要求确认，提示中显示目标块名称。取消不会删除块或改变当前块。
- [ ] 删除绑定块身份；即使名称重复，或确认期间块发生排序，也只删除用户确认的目标块。
- [ ] 复用导航票定义的选择规则：删除当前块后优先选择原顺序中的后一个，没有后一个时选择前一个；删除其他块不改变当前块，不另建一套回退逻辑。
- [ ] 允许删除最后一个块。零块页面没有当前块，显示可用的新增入口，刷新或关闭重开后仍然为空。
- [ ] 已保存的合法零块清单与尚未初始化的页面明确区分。原有新页面初始化行为不因支持零块清单而意外改变。
- [ ] 第二设备打开零块页面时也保持为空，不能用旧缓存或默认播种重新创建块。
- [ ] 从零块页面通过现有新增入口创建第一个块后，可正常选择和编辑；侧栏新增入口接入后使用相同空页面语义。
- [ ] 删除继续沿用现有块清单与本地布局清理范围，不增加服务端孤立正文删除或块回收站。
- [ ] 远端删除无需本机再次确认；本机当前块按导航票规则处理，不能残留已删除块的正文界面。
- [ ] 测试覆盖取消、同名目标、最后一块、重新初始化和旧缓存；真实浏览器验证删除后重开、第二设备打开及空页面再新增。
