# 分块工作区：拖拽排序、置顶置底与跨设备布局记忆

Status: ready-for-agent

## 问题陈述

从用户视角看，分块工作区（block workspace）目前有六个痛点：

1. **调整块顺序只能一格一格点。**
   块（block）的重排只有「上移」「下移」两个按钮，每次交换一个位置。把第 15 块挪到第 1 位要点 14 次。
2. **没有一步到顶或到底的操作。** 长距离移动没有快捷方式。
3. **块的高度和折叠状态换设备就丢。**
   这些状态只存在当前浏览器里。在手机上打开同一个页面，所有块回到默认高度、全部展开，布局要重调一遍。
4. **markdown 标题的折叠状态刷新就没了。**
   折叠起来的标题段落，页面一刷新全部展开，每次都要重新折叠。
5. **只有顶部能加块。** 「Add
   Block」按钮只在列表顶部。块多时看到底部要加块，得先滚回顶部。
6. **手机上调不了块高度。** 块底部的高度拖拽手柄只响应鼠标事件，触摸完全无效。

此外，支撑这些功能的块清单（manifest）同步机制有两个已实测确认的缺陷，会在本次新增状态后被放大：

7. **块清单每次改动都全文重传。**
   同步层用「删除全文 + 插入全文」构造 OT 操作。改一个字段要传整份文档。
8. **两端并发修改块清单会损坏数据。**
   两个客户端同时写块清单，OT 会把两份 JSON 缝在一起，导致解析失败或块 id 被改坏。

## 解决方案

从用户视角看：

- 块头部左侧出现**拖拽手柄**，按住可以直接把块拖到新位置，松手生效。
- 块头部的移动类操作收进一个「更多」菜单，里面有**上移、下移、置顶、置底**四项。
- **块高度、块折叠状态、markdown 标题折叠状态跟着页面走，不跟着设备走。**
  在电脑上调好的布局，用手机打开同一个页面就是同样的布局；折叠的标题刷新后仍然折叠。
- 块列表**底部也有一个「Add
  Block」按钮**，从底部添加的块出现在列表末尾，从顶部添加的仍然出现在开头。
- **手机上可以拖动手柄调块高度**。
- 块清单同步改为最小差异传输，并加上损坏检测与自愈，用户感知是「多设备同时打开时块不会莫名丢失或变形」。

## 实现决策

### 布局状态的落点与语义

- 块的布局状态（高度、块折叠、markdown 标题折叠）存进**块清单**（manifest），也就是那份协同文档。
- 这意味着布局状态**对该页面的所有查看者共享**。Rustpad 没有账号系统，跨设备同步与个人视图隔离二选一，本次选跨设备同步。目标场景是单人多设备，此时「共享」等价于「同步」。
- 协同文档是永久持久化的（服务端启用了 SQLite；清理任务只回收内存映射，下次访问会从数据库重新载入），所以布局状态不会因为页面闲置而丢失。
- 这条决策写入 ADR（见「后续说明」）。

### 块条目的结构

块条目新增三个可选字段。旧清单读到即为「未设置」，走迁移路径：

```ts
type BlockInfo = {
  id: string;
  title: string;
  language: string;
  height?: number; // 未设置时按默认值渲染
  collapsed?: boolean; // 未设置时按展开渲染
  folds?: unknown; // Monaco 折叠 memento，原样透传
};
```

- `folds`
  **原样存 Monaco 的折叠 memento**，不做压缩或转格式。Monaco 自己校验它：非数组直接忽略，每个折叠区带内容校验和，对不上就跳过该区。这正是让折叠记录在内容变动后自愈的机制，自定义格式会丢掉它。
- 块清单的 `title` 字段（文档标题）语义不变。

### markdown 折叠的读写

- 通过编辑器的折叠贡献（contribution）取得和恢复折叠状态，不走整个编辑器视图状态。已确认整体视图状态的恢复接口要求光标状态和视口状态同时存在，只传折叠部分会被完整忽略。
- **只记折叠，不记滚动位置和光标位置。**
  滚动是高频事件，写入协同文档成本高；且两台设备同时开着时会互相拉扯视图。
- 写入触发点是编辑器的「隐藏区域变化」事件（公开 API）。该事件在内容变更导致折叠重算时也会触发，因此写入前必须去抖并与上次已保存的 memento 比对，只在真正变化时写。
- 恢复时机需要实测确定：折叠范围是异步去抖计算的，内容同步完成后立刻恢复会因为折叠区尚未算出而无效。恢复逻辑要等到折叠模型就绪。

### 块高度的交互

- 高度拖拽手柄从鼠标事件改为指针事件（pointer
  events），配合指针捕获。指针事件是鼠标事件的超集，鼠标行为不变，同时获得触摸支持。
- 高度范围沿用现有上下限。

### 拖拽排序

- 使用 framer-motion 的 `Reorder` 组件族与
  `useDragControls`。该库已是直接依赖（同时也是 Chakra
  UI 的依赖），**不引入新依赖**。
- 关闭组件自带的整项拖拽监听，改由块头部的专用拖拽手柄通过拖拽控制器发起，避免整块可拖导致编辑器内选不中文字。
- 布局动画限定为**只动位置、不动尺寸**。尺寸动画会持续触发 Monaco 的自动布局重算，多个编辑器同屏时会卡顿。
- **拖拽期间只改本地顺序，松手才写块清单。**
- 提交时按块 id 在当前清单数组里重新定位，而不是用本地数组整份覆盖。这样拖拽期间其他设备的增删不会被抹掉。
- **不做边缘自动滚动**。framer-motion 的拖拽不提供该能力，长距离移动由置顶/置底覆盖。

### 块头部布局

块头部按以下顺序排列：拖拽手柄 · 折叠开关 · 连接状态点 · 标题 · 语言 · 复制 · 导出 · 更多菜单 · 删除。

上移、下移、置顶、置底四项收进「更多」菜单（用 Chakra 的菜单组件）。移动类操作是低频操作，收进菜单不损失可达性，同时避免窄屏上头部塞不下。

### 添加块的位置

添加块的操作增加位置参数。顶部按钮前插，底部按钮追加。块数为 0 时只渲染顶部按钮。

### 块清单同步：全量替换改最小差异

- 现有的无头 OT 客户端用「删除全文 + 插入全文」构造操作。改为与 Monaco
  OT 客户端相同的**公共前后缀差异**算法。
- 该算法目前内联在 Monaco
  OT 客户端里，是移动端输入法失同步修复的产物，含 UTF-16 代理对边界处理。本次**提取为独立纯函数模块**，两个 OT 客户端共用。
- 提取必须是**零行为变更的纯搬移**，且测试先行——这段代码是已知的高风险区。

原型实测数据（用仓库自己的 wasm OT 实现跑的并发场景），支撑上述决策：

| 场景                            | 全量替换                 | 最小差异                                         |
| ------------------------------- | ------------------------ | ------------------------------------------------ |
| 改 2224 字节清单里的一个高度值  | 每次传 2718 字节         | 每次传 17 字节                                   |
| 两端改不同块                    | 两份 JSON 拼接，解析失败 | 正确合并                                         |
| 两端各加一个块                  | 两份 JSON 拼接，解析失败 | 正确合并                                         |
| 两端改同一个高度值（420 / 500） | 解析失败                 | 得到 4250，解析通过但值无意义                    |
| 一端删块、一端改同一块标题      | 解析失败                 | 块 id 变成 `XYZccc`，解析通过但语义损坏          |
| 两端同时拖拽排序                | 解析失败                 | 3 块变 5 块，id 重复，解析通过但语义损坏         |
| 两端同时给空文档播种            | 解析失败                 | **仍然解析失败**（无公共前后缀，退化为全量替换） |

结论：最小差异消除**语法**损坏，消除不了**语义**损坏。改成一行一个块的 JSONL 格式也试过，同样的语义损坏照样出现——换序列化格式救不了。因此配套加下面的防护，而不是重建同步层。

### 块清单的损坏防护

- **播种自愈**：客户端播种块清单后，若下一次收到的服务端内容解析失败，用最近一次有效清单重写服务端。这覆盖唯一一个不需要人操作就会发生的并发场景——两台设备同时首次打开同一个新页面，各自自动播种。
- **结构校验**：解析后剔除 id 不合法的块条目、去除重复 id。块 id 由固定规则生成（6 位小写字母数字），可以据此判定。
- 人为的并发结构修改（同时在两台设备上拖块）概率接近零，不为它设计。该天花板用仓库的
  `shortcut:` 注释标记，写明限制与替换触发条件。

### 布局状态的迁移与本地镜像

- **迁移**：块清单里该块**没有**布局字段时，把本地遗留的高度和折叠值写进清单。一次性。多设备时先打开的那台生效。
- **本地镜像**：从清单读到的布局值镜像回本地缓存，供下次首屏在连上服务器之前直接渲染，避免默认高度闪一下再跳。块快照结构跟着扩展布局字段（它本来就是清单的本地镜像）。

### 本地存储配额治理

- 快照写入加异常保护，写失败不抛出。
- 捕获到配额溢出时，按最后访问时间**淘汰其他页面的快照**并重试；仍然失败则降级为只存块元信息、不存正文。
- 降级顺序的依据：服务端有永久持久化，正文丢了还能从服务端取；块元信息丢了才会找不到块。
- 删除块时清理该块遗留的本地布局记录。
- 快照模块的存储对象改为可注入，以便测试驱动配额异常。

### 模块划分

新增两个纯逻辑模块，改造一个既有模块：

- **块清单操作模块**（新）：添加（指定位置）、删除、移动（上/下/置顶/置底）、更新块字段、更新布局、解析（含拼接损坏恢复）、结构校验、遗留布局迁移。全部是纯函数。块清单 React 钩子退化为「同步 + 状态」的薄壳，转换逻辑一律走这里。
- **文本差异模块**（新）：公共前后缀差异，产出 OT 操作。两个 OT 客户端共用。
- **块快照模块**（改造）：存储对象可注入，加入配额淘汰与降级。

## 测试决策

### 什么是好测试

只测**外部行为**，不测实现细节。判据是「业务意图变了，测试必须失败」。例如：断言「置顶后该块在数组首位、其余块相对顺序不变」是好测试；断言「调用了某个内部函数」不是。

本次所有自动化测试都跑在**纯函数接缝**上，不 mock
React、Monaco 或 WebSocket——那些 mock 的成本远超被测逻辑本身的价值。

### 先例

仓库已有一处同型测试：输入法门控模块（纯逻辑，位于 `src/`）配一个测试文件（位于
`scripts/`），用 Node 内置的 `node:test` 与 `node:assert/strict`，直接 import
TypeScript 源码，`node --test` 可直接执行。本次全部沿用这个形态。

新增 `npm test` 脚本，一条命令跑完 `scripts/`
下所有测试文件（含现有的输入法门控测试）。**CI 不动**——目前只构建 Docker 镜像，本次不改这一点。

### 被测模块与用例

**文本差异模块**

- 纯追加、纯删除、中间替换、首尾替换、全量替换、空串到非空、非空到空、无变化。
- UTF-16 代理对边界：差异边界落在代理对中间时不得切开。
- 断言产出操作的基准长度等于原文长度、目标长度等于新文长度，且应用后结果等于新文。
- 这组测试要**先写、先通过**，再替换 Monaco
  OT 客户端里的内联实现——那是移动端输入法失同步的修复点，是本次最高回归风险。

**块清单操作模块**

- 移动：上移、下移、置顶、置底；边界情况（首位上移、末位下移、单块、空清单、id 不存在）均为无变化。
- 添加：顶部前插、底部追加；新块带默认布局。
- 删除：移除指定块，其余顺序不变。
- 更新布局：只改目标块，其余块与清单其他字段不变。
- 解析：正常清单、空文本、非法 JSON、**两份 JSON 拼接**（并发播种的产物）。
- 结构校验：非法 id 剔除、重复 id 去重、合法清单原样通过。
- 迁移：清单无布局字段时采用遗留值；清单已有布局字段时**不覆盖**。

**块快照模块**

- 注入一个写入时抛配额异常的存储对象，断言：不向外抛异常；触发淘汰后重试；重试仍失败时降级为只存元信息。
- 存取往返：写入后读出结构一致。
- 读到损坏内容时返回「无快照」而不是抛异常。

**并发 OT 集成测试**

骑在文本差异模块与块清单操作模块之上，不新增模块。用 wasm
OT 实现驱动上表中的并发场景，断言**当前已知行为**（包括已知会损坏的两个场景）。这类测试的作用是：以后有人改差异算法或同步策略时，行为变化会被显式暴露出来，而不是悄悄退化。

### 不做自动化、必须实机验证的

- 拖拽手柄的手势行为，含手机触摸。
- 20 块同屏拖拽的流畅度。
- markdown 折叠的恢复时机（依赖 Monaco 异步折叠计算）。
- 高度手柄在触摸设备上的拖拽。
- 跨设备布局同步的端到端效果。
- 块头部在窄屏上的排布。

  只有共享的文本差异模块会被普通模式的 OT 客户端复用，那是零行为变更的提取。
