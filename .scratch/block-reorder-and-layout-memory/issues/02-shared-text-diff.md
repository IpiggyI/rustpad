# 02: 抽出共用文本差异模块，无头客户端改用最小差异

**What to build:**
块清单的每次改动只在网络上传输变化的部分，而不是整份文档重传。两台设备改不同块时，两边的改动都保留，不再被缝成一份无法解析的文本。完整背景见同目录
`spec.md`。

公共前后缀差异算法目前内联在 Monaco
OT 客户端里，是移动端输入法失同步修复的产物，含 UTF-16 代理对边界处理；无头 OT 客户端则是另一套「删除全文 + 插入全文」。本票把前者提取为共用纯函数，两个客户端统一走它。

**这是本批次回归风险最高的一票**：改动点正是移动端输入法失同步的修复处。必须测试先行，且对 Monaco
OT 客户端只做零行为变更的纯搬移。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 存在一个不依赖 React / Monaco /
      DOM 的纯函数模块，输入新旧文本、输出对应的 OT 操作
- [x] 该模块的测试覆盖：纯追加、纯删除、中间替换、首尾替换、全量替换、空串到非空、非空到空、无变化
- [x] 有 UTF-16 代理对边界用例：差异边界落在代理对中间时不得切开
- [x] 每个用例断言产出操作的基准长度等于原文长度、目标长度等于新文长度，且应用后结果等于新文
- [x] 上述测试在改动任何既有代码**之前**先写好并通过
- [x] Monaco OT 客户端与无头 OT 客户端都改用该模块，代码库中不再有第二份实现
- [x] Monaco OT 客户端的改动是零行为变更的纯搬移
- [x] 改一个块清单字段产生的操作显著小于整份清单（原型实测基准：2224 字节的清单改一个高度值，操作从 2718 字节降到 17 字节）
- [x] 若尚不存在，添加一个一条命令跑完所有测试文件的 npm 脚本
- [x] 类型检查通过、测试通过
