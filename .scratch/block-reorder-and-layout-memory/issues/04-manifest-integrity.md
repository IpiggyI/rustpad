# 04: 块清单损坏防护：结构校验与播种自愈

**What to build:**
两台设备同时首次打开同一个新页面时，块清单不会被写成无法解析的内容。一旦发生损坏，客户端自动用最近一次有效版本修复服务端。id 不合法或重复的块条目在读取时就被剔除，损坏不会以「看起来正常」的形式留在页面里。完整背景见同目录
`spec.md`。

「两端同时给空文档播种」是唯一一个**不需要人操作就会发生**的并发场景 —— 两台设备同时首开同一新页面，各自自动播种，此时没有公共前后缀可用，差异算法退化为全量替换，两份 JSON 被缝在一起。人为的并发结构修改（同时在两台设备上拖块）概率接近零，本票不为它设计。

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] 解析遇到两份 JSON 拼接的内容时不抛异常
- [ ] 客户端播种块清单后，若随后收到的服务端内容解析失败，用最近一次有效清单重写服务端
- [ ] 测试输入覆盖：拼接损坏文本、含非法 id 的清单、含重复 id 的清单、合法清单原样通过
