# 02：粘贴图片、上传按钮和打开原图

**What to build:**
在块编辑器和单文档编辑器里，粘贴图片或用"上传图片"按钮选图，都会上传图片并在正文插入图片引用；按住 Ctrl 或 Cmd 点击图片引用，在新标签页打开原图。规则见同目录
`spec.md` 的"前端（第一期）"一节，那一节是本票的约束。服务端接口由 01 提供。

**Blocked by:** 01

**Status:** ready-for-human

- [x] 剪贴板 `text/plain` 非空时照原样粘贴文字，不上传
- [x] 剪贴板只有图片时上传，并插入 `![image](api/images/<图片id>.<扩展名>)`；多张按顺序用换行分隔；有选区时替换选区
- [x] 编辑器只读时不拦截粘贴
- [x] 上传期间只在本机显示"上传中"标记；插入位置跟随编辑移动，上传期间远端插入文字后，图片引用仍落在原来的逻辑位置
- [x] 插入作为本地编辑经 OT 同步，另一个客户端看到同样的文本
- [x] 失败时移除标记，toast 说明原因（未开启、格式不支持、超过 10 MB、网络错误）；超限或格式不对时不发请求
- [x] 每个块头部和单文档头部各有一个"上传图片"按钮，可多选，只接受四种格式
- [x] 所有语言都能 Ctrl 或 Cmd 点击图片引用，在新标签页打开按当前页面地址解析出的完整地址
- [x] 类型检查通过
- [x] 前端测试覆盖粘贴规则和链接识别，至少一条在规则写反时会失败
- [x] 浏览器测试：在真实页面里粘贴一张 png，正文出现图片引用，该地址能读回 `image/png`
- [ ] 实机验证：手机上用"上传图片"按钮从相册选图
- [ ] 实机验证：通过局域网 IP 的纯 HTTP 页面粘贴截图

## Comments

实现由 Codex 车道 `gpt-6.1-sol` 完成（会话 `01a0fd4f-a093-7fd0-aab4-104e41b559a6`），代码在 `src/imagePaste.ts`、
`src/ImageUploadButton.tsx`，接入点在 `src/BlockEditor.tsx` 和 `src/SingleDocView.tsx`。

首轮交付在真实浏览器里失败：编辑器有焦点时粘贴图片没有反应。原因是 monaco-editor 0.52 自带的粘贴控制器在编辑器容器上以捕获阶段监听
`paste`，剪贴板带文件且编辑器有焦点时，它先调用 `preventDefault()` 和
`stopImmediatePropagation()`，事件到不了挂在内层节点上的监听器。返工后监听器挂在 document 的捕获阶段，按事件路径只处理本编辑器的粘贴。

验证：`npm run check` 通过；`npm test` 243 项通过；`node scripts/imagePaste.browser.mjs`
在单文档和分块两种模式下各 5 项通过，包括上传中远端插入文字后引用仍落在原位置、Ctrl 点击打开完整地址。整套 `npm run test:browser`
回归通过；其中 `clipboardFallback.browser.mjs` 需要可达的局域网来源，`100.113.202.113` 在 Chromium 里返回 502，换用
`192.168.0.46` 后通过。

剩下两项实机验证留给人工。浏览器测试里的粘贴是合成事件，跑在 `127.0.0.1` 上，证明不了真实剪贴板和纯 HTTP 来源的行为。
