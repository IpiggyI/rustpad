# 普通模式折叠记录存入旁路协同文档

普通模式的折叠记忆必须跨设备，因此不能只放浏览器本地存储。Rustpad 没有账号系统，跨设备同步与个人视图隔离二选一，与 ADR 0001 同一取舍：折叠记录放进协同文档，该文档的所有查看者看到同一份折叠。

普通模式没有块清单。折叠记录不进正文、不改服务端 `PersistedDocument`（仍只有 text / language / title），而是另开一份协同文档，id 为 `folds:${文档id}`，内容是按语言分键的 Monaco 折叠 memento JSON。本地存储降为缓存：首屏、以及卸载时的同步写出。连上旁路文档之后，服务端记录才是数据源。

## 决策依据

主要使用场景仍是一个人多台设备打开同一份文档。块模式已经把折叠放进块清单；普通模式若只记本机，同一功能在两种模式下语义不一致。旁路文档复用现有 `RustpadHeadless` 与字符级 OT，不必改协议和数据库。

## 后果

- 同一普通模式文档的其他查看者会看到相同的折叠。这是本决策的直接代价。
- 字符级 OT 承载 JSON 的语义损坏天花板与 ADR 0002 相同。折叠 JSON 体积小，写入走最小差异；并发两端改不同语言的折叠，可能交错。可接受范围与块清单相同：单人多设备。
- 空旁路文档两端同时用本机缓存播种，是 ADR 0002 已记录的播种冲突。只允许初始化时播种一次；之后服务端为准，不得再用本机缓存覆盖服务端。
- `#folds:…` 不能当作普通模式文档 id 打开，否则会把旁路 JSON 当正文编辑。

## 推翻这个决策的条件

Rustpad 引入账号或会话身份，折叠可以按人分片；或服务端为普通模式增加一等折叠字段，且其合并语义优于整份 JSON 的字符级 OT。
