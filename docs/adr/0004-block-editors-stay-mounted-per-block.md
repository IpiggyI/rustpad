# 块编辑器按块常驻挂载，展示方式只控制可见性

单块展示一次只显示当前块。最直接的实现是只挂载当前块的编辑器，切块时卸载上一个。这条路不能走：当时的
`Rustpad.dispose()` 是同步的，它关闭连接，却不发送 `buffer`、也不等待
`outstanding`
的服务端确认，所以卸载会丢掉用户刚敲进去、尚未确认的编辑；撤销历史又属于文本模型，模型随卸载消失，撤销记录也就没了。

于是只有两个落点：把协同状态和内容监听从编辑器解绑到模型，让一个编辑器实例能换模型；或者让每个块的编辑器一直挂着，展示方式只决定谁可见。我们选后者。

## 决策依据

堆叠展示在所有块都展开时，本来就为每个块挂一个 Monaco 实例和一个协同连接。这是应用原有的默认路径。所以"始终挂载"并不超出应用已经在付的开销，它只是取消了"折叠某个块以释放连接"这一条省资源的途径。

反过来，把 OT 状态从编辑器迁到模型，要改动 `src/rustpad.ts`
的绑定方式，而这项改造的唯一消费者就是单块展示本身。

## 后果

- **折叠一个块不再释放它的协同连接。**
  这是本决策的直接代价。同时它消除了一处静默丢数据：折叠原本会走
  `dispose()`，未确认的编辑就此丢失。
- 挂载只能按块 id 决定，不能按展示方式，也不能按
  `collapsed`。两种展示必须共用同一棵父组件树，组件不能在两个展示分支之间搬移，否则 React 仍会卸载重建。
- 隐藏非当前块的正文要用保留明确尺寸的容器加 `visibility:hidden`，不能用零尺寸或
  `display:none`，否则 Monaco 会测到零尺寸；重新显示时调用 `layout()`。
- 切走之前要先结束当前的输入法组合，不能在组合中途隐藏编辑器。
- 常驻连接消除了"隐藏后收不到远端编辑"这一类陈旧，但不足以让复制导出正确：`resolveBlockContent()`
  必须改掉直接返回旧快照、以及超时后把快照当成功返回这两条，改为先等本地待确认操作，再走一次新的完整服务端读取，失败即报错。
- `Rustpad.dispose()`
  仍会在页面拆除时走到，它需要一个可等待的关闭契约：先停止接受新输入，按既有确认顺序发完
  `outstanding` 和
  `buffer`，成功后再关闭连接。发完就关（`RustpadHeadless.dispose()` 里
  `flushThenClose()`
  的形状）只是尽力发送，不能证明服务端收到，因此不能宣称为无损关闭。浏览器退出不等待 Promise，未同步退出提示必须保留。

## 推翻这个决策的条件

一个页面的块数量增长到 N 个常驻编辑器与连接的开销可实测地不可接受，或者真实浏览器测量表明隐藏挂载仍会破坏撤销、光标、滚动或输入法。届时"始终挂载不超出现有开销"这个前提消失，解绑模型的改造才值得做。
