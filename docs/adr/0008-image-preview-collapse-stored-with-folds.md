# 图片预览的收起状态跟标题折叠记录存在一起

图片预览可以收起，收起状态和标题折叠一样在设备之间共享。我们不为它新开存储，而是放进折叠记录已有的位置：块模式在块清单的每个块上加
`collapsedImages` 字段；单文档模式在旁路协同文档 `folds:<文档id>` 的 JSON 对象里加保留键
`@collapsedImages`。两处的值都是被收起的图片文件名（`<图片id>.<扩展名>`）排序后的数组。

## 考虑过的方案

- **单文档模式另开一份旁路协同文档。** 例如 `images:<文档id>`。数据形状更干净，但每打开一个文档就多一条 WebSocket
  连接，`parseHash` 还要再保留一个前缀。
- **按行号记录。** 行号会随编辑移动，远端插入一行就会让收起状态落到错误的图片上。按图片文件名记录不受行移动影响，代价是同一张图片在一个块里被引用两次时，两处一起收起。

## 后果

- [ADR 0003](0003-single-doc-folds-in-sidecar-collab-doc.md)
  的旁路文档原本只以语言为键。现在多了一个保留键，所有遍历这份对象的代码（写本地缓存、播种、恢复折叠）都必须跳过它，不能把它当成某个语言的折叠记录，也不能在写回时把它丢掉。键名以
  `@` 开头，Monaco 的语言 id 不会出现这个字符。
- 收起操作和折叠写入必须走同一条合并路径，否则两个写入者会互相覆盖对方的键。
- 块清单里每个块的新字段要经过所有重新构造块数据的路径；[ADR 0005](0005-empty-manifest-is-a-real-page-state.md)
  记录过根字段在这类路径上丢失的情况。
- 被删掉的图片引用，其收起记录可能残留在数组里。残留不影响显示，下次写入时可以顺带清理。
