# 块布局状态存入共享块清单

Rustpad 没有账号系统，服务端只认页面 id，不认「谁在看」。因此布局状态（块高度、块折叠、块内 markdown 标题折叠）只有两个可能的落点：浏览器本地存储，或者页面的协同文档。前者做不到跨设备，后者做不到个人视图隔离——没有第三种选择。我们选后者：布局状态作为可选字段存进块清单。

## 决策依据

主要使用场景是一个人在多台设备上打开同一个页面。此时「共享」与「同步」是同一件事：在电脑上调好的高度，用手机打开就该是同样的高度。相反，布局存在本地意味着每换一台设备就要把布局重调一遍，这正是当前的痛点。

块清单是协同文档，布局状态因此与块内容同寿：块内容能保存多久，布局就能保存多久。这不等于永久保存。默认配置没有数据库（`rustpad-server/src/lib.rs:82`），清理器会移除超过保留期未访问的文档（`rustpad-server/src/lib.rs:196`），只有部署时设置
`SQLITE_URI` 才有持久化。

## 后果

- **同一页面的其他查看者会看到相同的布局。**
  一个人改了块高度或折叠了某个块，所有打开该页面的客户端都会跟着变。这是本决策的直接代价，不是缺陷。
- 布局改动会产生协同文档写入，因此只在明确的用户操作（拖高度、点折叠、折叠 markdown 标题）时写，不跟随滚动或打字。
- 本地存储降级为块快照的一部分，只用于首屏在连上服务端之前抢先渲染，不再是数据源。

## 推翻这个决策的条件

Rustpad 引入了账号或会话身份，使服务端能区分「谁在看」。那时布局状态可以按身份分片存放，「跨设备同步」与「个人视图隔离」不再互斥，本决策的前提消失。
