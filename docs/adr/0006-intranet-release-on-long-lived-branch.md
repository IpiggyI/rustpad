# 内网版放在长期分支上，不在主分支里用开关区分

内网版要在没有互联网的环境里双击运行，所以它和在线版在几处行为上不同：Monaco 改为本地打包、不带
`#`
的地址进入首页、服务端启动时打印访问地址并自动打开浏览器。我们把这些改动放在长期分支
`intranet`
上，主分支保持在线版的行为。每次发布内网版之前，用 merge 把 main 合并进来。

## 考虑过的方案

另一条路是不开分支：前端用构建模式（`--mode intranet`）区分，服务端用 `.env`
开关区分，主分支默认构建出来的仍是在线版。按决策时的统计，内网版独有的代码改动约 250 行，大部分是新文件，用开关完全能承载。

我们没有选它，原因是内网版以后的要求还不确定。用开关意味着每一项内网版需求都要在主分支里做成“可关闭的”，内网版越往后走，主分支里平时不生效的代码就越多。分支可以让内网版独立演进，不用每次都考虑在线版。

## 后果

- **合并会有冲突。** 内网版要改动
  `src/BlockPageView.tsx`、`src/useHash.ts`、`src/index.tsx` 和
  `rustpad-server/src/main.rs`，其中 `src/BlockPageView.tsx`
  有一千多行，是主分支上修改最频繁的文件。main 每次改到这些位置，合并时都可能要手工解决冲突。
- **两边都需要的修复先进 main。**
  例如复制降级，在线版通过 http 访问时同样需要。这类修复先在 main 上提交，再通过合并进入
  `intranet`，不要在分支上单独修。
- 分支上不设构建模式或开关，内网版的行为无条件生效。

## 推翻这个决策的条件

如果合并冲突成了每次发布的主要工作量，或者内网版和在线版的差异长期稳定在少数几处，就改回“主分支加开关”：把分支上的差异收进构建模式和
`.env` 开关，然后删除 `intranet` 分支。
